# Local ontology observer and direct warnings

Approved in chat: persistent auto-refresh observer, direct warnings, per-rule
status, test output, run-check and fix-request affordances. Implement inline with
TDD and an independent final review, then publish a PR including v0.2.0 changes.

- [x] Direct systemMessage warnings for failing checks, including failed evidence
  with no working-tree changes; preserve bounded Stop continuation.
- [x] Stdlib localhost server and static browser UI. Refresh every three seconds;
  show rules, current evidence, source freshness, review findings and open questions.
- [x] Explicit command allowlist in ontology/checks.json, exact domain/rule match,
  token-authenticated API, loopback bind and Host/Origin validation. Never execute
  gate annotations or browser-supplied command strings. Run one check at a time.
- [x] Actual command output, last-run time, bounded output preview, copyable fix
  request. UI must visibly report loss of connection and unavailable checks.
- [x] Real HTTP tests for authorization, config drift, arbitrary commands,
  fail/repair/stale states, malformed config; render and exercise in browser.
- [x] Package docs/version, full relevant suites, independent review, PR.

Design decisions: a local browser panel is available without depending on an
unverified embedded Codex UI. Copy fix request puts the human in control of which
chat receives it. Config commands require an explicit click and display of argv;
loading a repository never runs a test. No automatic agent sends or source edits.
